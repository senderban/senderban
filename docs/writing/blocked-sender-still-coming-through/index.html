Why are blocked emails still coming through?

Blocked emails still come through for four reasons: the block files the mail into Spam or Junk instead of refusing it, the mail arrived before the block, the sender wrote from an address the block does not cover, or the block lives in one mail app instead of on the mail server. Each has a different fix, and only the last one is about where the block is kept.

Key facts

  • Gmail's Block sends a sender's future mail to Spam, and Outlook's Blocked senders list moves it to the Junk Email folder (help pages, read 2 November 2026). The mail still arrives, in another folder.
  • A block list kept in a mail app on one computer is not on the server: Microsoft's archived note on Outlook 2013 says such lists "are maintained only on that client".
  • The new Outlook "does not support blocking senders for third-party accounts like Gmail, Yahoo, iCloud", Microsoft's page says (read 2 November 2026).
  • On a personal Outlook.com mailbox on 1 November 2026, a rule Senderban wrote on Microsoft's server took about 0.6 s from the click to a checked block, and mail from the blocked address went to Deleted Items, not the Inbox.
  • On iCloud Senderban writes no server rule. On 1 November 2026 one address block moved two earlier mails and one new mail out of the Inbox, but only while the app runs; with it closed, your phone sees the mail.

Do blocked emails still come through?

Usually, yes. On Gmail and Outlook a block decides which folder the mail lands in; the sender can still send it and the server still accepts it. Google's help page on blocking a sender says that after a block "all future emails from them go to Spam". Microsoft's page on blocking senders in Outlook says "Outlook automatically moves messages from that sender to the Junk Email folder", and, of classic Outlook, "The blocked person can still send you mail". Both were read on 2 November 2026.

So start with where the mail is. These questions, in this order, separate the four causes:

What you see Cause What to do
The mail is in Spam, Junk or Trash The block files mail, it does not refuse it Nothing: the block works. To delete it instead, use a filter or rule
The mail is older than the block A block acts on mail that arrives after it Move or delete that mail yourself
Same sender, a different address An address block covers that one address Block the domain, after checking what the domain rule matches
Filed on your PC, in the inbox on your phone The block lives in one mail app Make the block on the provider's website, where the server applies it

Is the block on the server or in one app?

A block can live in two places. A rule on the mail server acts on the mail as it arrives, so the phone, webmail and every mail app see the same result. A block list in a mail app on your PC acts only when that app has the mail in front of it, on that device. Microsoft's archived note on Outlook 2013 with an Outlook.com account says it plainly: if you use the Safe Senders and Blocked Senders lists in Outlook 2013, "the lists are maintained only on that client", while "if an email message is blocked by the Outlook.com service, the email message is not delivered to the Outlook 2013 clients". Its fix is to keep the list on Outlook.com instead (read 2 November 2026).

To check yours, block a second address of your own the same way, send a mail from it, and look on your phone. If the phone shows it in the inbox, the block is not on the server.

Why doesn't Block sender work in Outlook?

Three things in Microsoft's own pages explain most cases. These are the steps and limits on the Outlook help page, read 2 November 2026. In the new Outlook and Outlook.com the block is made like this:

  1. Select Settings, Mail, Junk email.
  2. To block one address, enter it under Blocked senders and select Add.
  3. To block a whole domain, enter it under Blocked domains and select Add.
  4. Select Save.

A rule acts on new mail. Microsoft's reference for Outlook rules describes "rules for incoming messages in the Inbox", so mail that was already in the Inbox stays there. And a domain in an Outlook rule is a text match: a rule for @brand.example also catches @brand.example.test, which is someone else. Graph has no exact-domain condition (ADR 0013).

Why are blocked emails still coming through in Gmail?

Gmail's Block covers one sender and moves their future mail to Spam, so a blocked mail in Spam means the block works. Google's steps, read 2 November 2026: open the sender's message, click More next to Reply at the top right, then Block "{sender}". The page speaks of future emails; it does not say the block moves mail already in your inbox.

When the same sender writes from a new address, the block does not cover it. Gmail has no domain block button; the free way is a filter on from:(@example.com) that deletes the mail. Our test of that search on 29 October 2026 found it also matched a longer, different domain and a word in a sender's display name: the steps and the measured table are in How do I block a domain in Gmail, and does it work?

Why are blocked emails still coming through on iPhone?

A phone shows the mailbox the server keeps. A rule on the server has already acted on the mail; a block made in a mail app on another device has not, so the phone sees the mail in the inbox. That is the lower half of the diagram above.

For an iCloud address, Apple's support guide page "Set up rules to filter email in Mail on iCloud.com" (read 2 November 2026) describes rules that filter incoming mail, "up to 500 rules". It also says "It may take up to 15 minutes for new or changed rules to take effect on incoming emails", so a mail in the first minutes after a new rule can still reach the inbox. Apple's page does not mention blocking senders, and the iPhone Mail app's own block setting was not tested for this post.

Where does Senderban help, and where does it not?

Senderban is a free, open-source Windows app. When new mail arrives it shows a Windows notification, and one click writes the block on the mail provider's server where the provider lets a program write a rule: a Gmail filter, an Outlook rule or a Sieve rule. One block list is shared by all the accounts you add. Where no rule can be written, it moves the mail itself, which has the same weakness as a block in one app.

Provider What a block becomes Where the mail goes Measured on a real account
Gmail / Workspace Gmail filter on Google's server, single addresses only Trash Yes: 0.75 s click to checked filter, 27 October 2026
Outlook / Hotmail / Microsoft 365 Outlook rule on Microsoft's server Junk or Deleted Items Personal account only: about 0.6 s, 1 November 2026
MXroute Sieve rule; optionally the MXroute blacklist for one address Junk or Trash; the blacklist refuses the mail Yes: full loop 30 October 2026, refusal 25 October 2026
Migadu, mailbox.org, Purelymail, other ManageSieve servers Sieve rule on the server Junk or Trash No: a local Dovecot server only, 31 October 2026
iCloud No rule: Senderban moves the mail while it runs Junk or Trash Yes: 3 mails moved out of the Inbox, 1 November 2026
Yahoo, AOL, GMX, Web.de No rule: Senderban moves the mail while it runs Junk or Trash No: a local Dovecot server only

What it does not do, as the README and ADRs state for v0.2.0:

  • No server rule on iCloud, Yahoo, AOL, GMX or Web.de. With Senderban closed a blocked sender's mail stays in the inbox, and your phone sees it.
  • No domain block on Gmail, and no Spam. A domain entry made on another account shows Gmail: not applied; a Gmail filter cannot file mail into Spam, so Gmail entries go to Trash.
  • An Outlook domain is a text match. Some domains are refused for that reason, and the list shows Outlook: not applied. A work or school account was not measured and may need an administrator's approval.
  • Refusing at the server is MXroute only, for single addresses, off until you switch it on. On the mailbox measured the sender got 550 High scoring spam message has been dropped; that depends on the spam-score limit in the MXroute panel.
  • On Outlook, mail that arrived before the block stays in the Inbox. On an Other (IMAP) mailbox, such as iCloud, a block also moves that sender's mail of the last 30 days out of the inbox.
  • It is not an email client. It does not send, sync or download message bodies, and it runs on Windows only.

If your mail is on Gmail, Outlook.com or a Sieve server, the provider's own steps above work without Senderban. What Senderban adds is the block from the notification, and one list applied to every account you add. See how it works and where it works.

What was not measured?

  • Gmail's own Block button and Outlook's own Blocked senders list on new mail. Their behaviour here is what Google's and Microsoft's pages say.
  • The iPhone Mail app's block setting, and Apple's rules on iCloud.com.
  • Outlook on a work or school account, and whether an Outlook domain rule also reads the sender's display name.
  • Senderban at Migadu, mailbox.org, Purelymail, Yahoo, AOL, GMX and Web.de: the same code ran against a local Dovecot server only.
  • More than one mailbox per provider. Each measurement above is one account on one day.
